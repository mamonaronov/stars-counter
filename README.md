# Stars Counter — Telegram-бот учёта посещаемости

Бот для группы ~50 студентов: отмечающие заводят занятия и отмечают присутствующих кнопками, студенты смотрят свой процент за любой месяц, университет получает Excel-отчёт. Один Python-процесс, один бот, SQLite.

## Возможности

- **Отметка присутствия кнопками.** Под сообщением — список студентов в два столбца; нажатие ставит ✅, повторное снимает. Отметки можно менять в любой момент, в том числе за прошлые занятия.
- **Занятия задним числом.** Дата выбирается кнопками (сегодня/вчера/позавчера/календарь) или текстом `12.09`, время — «сейчас», из шаблона или текстом.
- **Шаблоны занятий** (название, тип, время по умолчанию), общие для всех отмечающих.
- **Обязательные и свободные занятия.** Свободные учитываются только тем, кто пришёл, поэтому процент может быть выше 100.
- **Месяцы по занятиям, а не по календарю.** Отмечающий помечает занятие как последнее в месяце; следующее занятие автоматически открывает новый месяц. Конец месяца можно перенести, месяц переименовать или открыть обратно.
- **Excel-отчёт** за закрытый или текущий (промежуточный) месяц: лист с рейтингом «№ / ФИО / Процент» с цветовой шкалой и лист «Детали» с матрицей посещений.
- **Больничные и отпросы**: пропуски обязательных занятий за период считаются посещёнными; запись можно отменить.
- **Верификация студентов** одноразовой ссылкой `t.me/<bot>?start=v_…`, которую отмечающий пересылает студенту.
- **Запросы студентов** «меня забыли отметить»: уходят создателю занятия и видны всем отмечающим; кнопки «Отметить» / «Отклонить с комментарием», студент получает ответ.
- **Публичная статистика**: любой пользователь бота может посмотреть посещаемость любого студента за любой месяц.
- **Журнал действий**: кто, когда, с какой ролью и что сделал (отметки, роли, месяцы, студенты, отпросы, запросы). Виден отмечающим и выше. У каждого занятия своя история изменений.
- **Студенты**: добавление по одному или списком с предпросмотром, год поступления (курс), дата начала учёта, удаление с сохранением истории, восстановление.
- Бэкапы на диск по расписанию и при выключении, беззвучная копия БД суперадмину в Telegram, восстановление из бэкапа при повреждении файла.

## Как считается процент

```
процент = (посещённые обязательные + посещённые свободные + пропуски по уважительной причине)
          / все обязательные занятия периода × 100
```

- Свободные занятия, на которые студент не пришёл, нигде не учитываются.
- Пропуск обязательного занятия, попадающего в активный больничный/отпрос, считается посещением.
- У студента учитываются только занятия начиная с его даты «учитывать с» (по умолчанию — день добавления; при импорте и добавлении можно указать другую дату, потом — поменять в карточке студента) и до даты удаления.
- Если обязательных занятий в периоде нет, процент не считается.

## Роли

| Уровень | Роль | Что может |
|---|---|---|
| 5 | **суперадмин** | всё; задаётся `SUPERADMIN_TELEGRAM_ID` в `.env`, назначает главных админов |
| 4 | главный админ | назначает админов, может передать свою роль (сам становится админом) |
| 3 | админ | назначает главных отмечающих |
| 2 | главный отмечающий | назначает отмечающих, добавляет/удаляет студентов, может передать свою роль (сам становится отмечающим) |
| 1 | отмечающий | занятия, отметки, шаблоны, месяцы и отчёты, больничные, запросы, ссылки верификации, журнал |
| 0 | студент / гость | своя статистика и запросы (верифицированный); просмотр посещаемости любого (все) |

Каждый уровень может всё, что могут нижние. Назначить или снять роль можно только тому, кто ниже вас. Роли выдаются только верифицированным студентам. Отмечающий — тоже студент и отмечает себя наравне с остальными.

## Быстрый запуск

Нужны Docker + Docker Compose, токен от [@BotFather](https://t.me/BotFather), ваш Telegram ID (например, через [@userinfobot](https://t.me/userinfobot)).

```bash
cp .env.example .env
# заполните BOT_TOKEN и SUPERADMIN_TELEGRAM_ID

chmod +x deploy.sh
./deploy.sh            # systemd-юнит + docker compose up -d --build (нужен sudo)
docker compose logs -f bot
```

Без скрипта:

```bash
mkdir -p data backups
docker compose build
docker compose up -d
```

В логах ожидаются `SQLite WAL mode confirmed` и `Polling started`. Остановка: `docker compose stop bot` (перед выходом бот делает бэкап на диск; чтобы ждать без лимита — `docker compose stop -t -1 bot`).

Если Telegram с сервера недоступен напрямую, заполните `TELEGRAM_PROXY_URL=socks5h://proxy:11808` и поднимите рядом compose **mihomo-proxy** с Docker-сетью `telegram-proxy`; `./deploy.sh` сам добавит `docker-compose.proxy.yml`.

Локально без Docker (Python 3.11+):

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
DB_PATH=./data/database.sqlite3 BACKUP_PATH=./backups python bot.py
```

## Переменные окружения

| Переменная | Обязательно | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен бота |
| `SUPERADMIN_TELEGRAM_ID` | да | — | Telegram ID суперадмина |
| `TIMEZONE` | нет | `Europe/Moscow` | пояс для дат занятий, «сегодня» и журнала |
| `ORG_TITLE` | нет | `Посещаемость групп` | заголовок Excel-отчёта («… за период») |
| `DB_PATH` | нет | `/app/data/database.sqlite3` | путь к БД внутри контейнера |
| `BACKUP_PATH` | нет | `/app/backups` | каталог бэкапов |
| `BACKUP_INTERVAL_HOURS` | нет | `6` | период бэкапа на диск |
| `BACKUP_KEEP` | нет | `14` | сколько копий хранить |
| `TELEGRAM_BACKUP_INTERVAL_HOURS` | нет | `24` | как часто беззвучно слать копию БД суперадмину (`0` — выкл) |
| `LOG_LEVEL` | нет | `INFO` | уровень JSON-логов |
| `TELEGRAM_PROXY_URL` | нет | пусто | SOCKS5 для Telegram API |

## Первые шаги после запуска

1. Суперадмин пишет боту `/start` — видит полное меню.
2. **👥 Студенты → 📥 Импорт списком** — присылает список вида `Иван Иванов, 2023` (строка = студент). Бот показывает, кто и с каким годом будет добавлен, помечает ошибки и дубли; можно задать, с какой даты учитывать занятия. Подтверждение — кнопкой.
3. **🔗 Верификация** — выбрать студента, получить ссылку, переслать ему. Студент переходит по ссылке → бот его узнаёт.
4. **🎖 Роли** — назначить верифицированному студенту роль (например, главного отмечающего). Дальше он сам назначает отмечающих.
5. **📋 Шаблоны** — завести типовые занятия.

## Инструкция отмечающего

| Действие | Где |
|---|---|
| Создать занятие и отметить | ➕ Новое занятие → шаблон или вручную → дата → время → (название → тип) → экран отметки |
| Поменять отметки на прошлом занятии | 📅 Занятия → занятие → ✅ Отметить присутствие |
| Изменить название/дату/время/тип, удалить | карточка занятия |
| Закрыть месяц | 🗓 Месяцы и отчёты → Текущий → 🔚 Закрыть месяц → выбрать последнее занятие (или в карточке занятия «🔚 Последнее в месяце») |
| Перенести конец месяца / переименовать / открыть обратно | 🗓 → месяц → соответствующая кнопка |
| Отчёт Excel (закрытый или промежуточный) | 🗓 → месяц → 📑 Отчёт Excel; 📊 Сводка — рейтинг текстом |
| Больничный / отпрос | 🩺 → ➕ Добавить → студент → вид → с даты → по дату → комментарий; отмена — в карточке записи |
| Запросы студентов | 📨 Запросы (также приходят уведомлением создателю занятия) → ✅ Отметить / ❌ Отклонить |
| Ссылка верификации | 🔗 Верификация → студент |
| Журнал действий | 🕵️ Журнал действий; история конкретного занятия — в его карточке |
| Студенты (главный отмечающий и выше) | 👥 Студенты: список, добавить, импорт, удалённые; в карточке — имя, год, дата учёта, отвязать Telegram, удалить |
| Роли (главный отмечающий и выше) | 🎖 Роли → назначить/снять; передать главную роль |

В списках студентов можно прислать часть фамилии сообщением — список отфильтруется.

## Инструкция студента

- `/start` — меню. Пока аккаунт не верифицирован, доступны только «Посещаемость студентов» и «Помощь».
- После перехода по ссылке от отмечающего появляются **👤 Моя посещаемость** (любой месяц, список занятий со статусами ✅ ❌ 🩺 ➖) и **✉️ Запрос отмечающему** (выбрать месяц → занятие, где вас нет → написать сообщение). Ответ придёт сообщением.

## База данных, бэкапы, обновление

SQLite + aiosqlite, WAL, `foreign_keys=ON`. Схема версионируется через `PRAGMA user_version`; требуемая версия — `REQUIRED_DB_VERSION` в `config.py`, миграции — `migrations/NNN_*.sql`, применяются при старте (перед ними делается бэкап `pre_migrate`). Все запросы параметризованы.

Бэкапы через SQLite Online Backup API: по расписанию (`scheduled_*`), при выключении (`shutdown_*`), перед миграциями; хранится `BACKUP_KEEP` последних. Раз в `TELEGRAM_BACKUP_INTERVAL_HOURS` копия беззвучно уходит суперадмину; вручную — 🛠 Сервис → 📦 Прислать бэкап сейчас. Если при старте файл БД не проходит `integrity_check`, он откладывается как `database.sqlite3.damaged.*` и восстанавливается последняя копия из `backups/`.

Ручное восстановление:

```bash
docker compose stop bot
cp backups/scheduled_YYYYMMDD_HHMMSS_ffffff.sqlite3 data/database.sqlite3
rm -f data/database.sqlite3-wal data/database.sqlite3-shm
docker compose up -d
```

Обновление: `git pull --ff-only && ./deploy.sh`.

Логи — JSON в stdout (без токена). Ошибка в одном хендлере не роняет процесс; суперадмину уходит алерт. При старте и остановке суперадмин получает беззвучное уведомление.

## Структура проекта

```text
bot.py                 точка входа, один Bot(), polling с повторами, graceful shutdown
config.py              переменные окружения, REQUIRED_DB_VERSION
database/              движок (WAL, миграции, бэкап), модели, Repo, FSM-хранилище в SQLite
migrations/            SQL-схема
middlewares/           контекст, Actor (роль текущего пользователя), изоляция ошибок, дедуп callback
handlers/              сценарии: start, attendance, events, templates, months, requests,
                       excuses, students, roles, audit, service, fallback
keyboards/             inline-клавиатуры
services/              roles (иерархия), periods (месяцы), stats (процент), report (xlsx),
                       students (импорт), audit, jobs, alerts
states/                FSM
utils/                 время, форматирование, безопасные вызовы Telegram, сессия с прокси, логи
tests/                 юнит-тесты и сквозные сценарии через Dispatcher с фейковой сессией
deploy/, deploy.sh     systemd-юнит и установка
```

## Тесты

```bash
pip install -r requirements.txt
python -m pytest -q
```

Покрыто: расчёт процента (свободные, уважительные, даты учёта), разбиение на месяцы, права ролей, разбор списка студентов, Excel-отчёт, слой БД (миграции, бэкапы, восстановление повреждённой БД, одноразовые ссылки, отметки, запросы, отпросы, аудит) и сквозной сценарий: импорт → верификация → роли → шаблон → занятия → отметки → больничный → публичная статистика → запрос студента → закрытие месяца → отчёт → перенос конца месяца → журнал → передача роли → удаление студента → бэкап.
